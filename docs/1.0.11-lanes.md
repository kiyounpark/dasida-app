### 서버 배포 규칙 (🔒 10.02 밤)

- **`firebase deploy --only functions`(전체)는 아무 줄도 안 친다.** 브랜치마다 코드가 달라서, 전체 배포는 다른 줄 함수를 그 브랜치의 옛 껍데기(501)로 덮는다.
- 새 함수는 **자기 것만 이름으로**: 1줄 `--only functions:saveConsent,functions:getConsent` · 2줄 `--only functions:savePhotoNote` · 3줄 `--only functions:listPhotoNotes,functions:getPhotoNoteImage`. 언제든 해도 된다(아직 아무 학생도 안 부른다).
- **이미 학생이 쓰는 함수 `analyzePhoto`·`deleteAccount`는 2줄만, 그리고 조건부로**: 동의 문서가 없을 때(= 1.0.9·1.0.10·웹) 지금과 **똑같이 도는 걸 테스트로 먼저 보인 뒤** `--only functions:analyzePhoto`(또는 `deleteAccount`). 그 배포 시각을 보고서에 적는다.
- 웹 `deploy:proto`는 아무 줄도 안 한다.

### 그 밖에

- 운영 GA에 테스트 기록을 섞지 않는다 — 확인은 개발 빌드(`__DEV__`)에서.
- 학생 이름을 저장소에 쓰지 않는다(공개 저장소).
- `npx`는 rtk가 가로챈다 — `./node_modules/.bin/…`.
- 패키지를 더하면 `./node_modules/.bin/expo prebuild --clean` 뒤 `./node_modules/.bin/expo run:ios`(CLAUDE.md 3). 이번 판은 새 패키지 없이 되게 짰다 — 더해야 하면 먼저 말한다.

## 1줄 — 사진 동의 화면

**만드는 것:** 온보딩(닉네임·학년) 다음에 뜨는 동의 화면 한 장 + 동의 서버 저장·읽기 + 계정 관리 출구 + 방침·문구.

**화면 (🔒 10.02 밤 — 문구는 초안, 만들 때 `target-student`로 한 번 읽힌다):**

```
☐ 전체 동의
☐ [필수] 사진을 분석하려고 다시다 서버·OpenAI(미국)로 보내
☐ [필수] 내 노트, 계정에 저장 — 다른 폰·아이패드에서도 보여
☐ [선택] 내 사진으로 분석 정확도 높이기 (30일 뒤 지워)
        [다음]            ← 필수 둘 다 체크해야 눌린다
        계정 관리 >        ← 작은 글자. 누르면 로그아웃 / 계정 삭제
```

- 줄 순서·필수 여부는 약속 파일 `CONSENT_KINDS`·`CONSENT_REQUIRED`로 그린다(숫자로 박지 않는다).
- 띄우는 조건 = `needsConsentScreen(doc)`. 기존 가입자도 다음 실행 때 같은 화면(콜드 스타트 `app/index.tsx`와 `app/_layout.tsx`의 문 둘 다).
- 동의 문서는 서버(`saveConsent`/`getConsent`) + 기기 사본(`features/consent/consent-store.ts`, 줄 0이 만들어 둠). 오프라인이면 기기 사본으로 정하고, 서버 저장 실패는 다음 실행에 다시.
- **누른 방식 `via`**: [전체 동의]로 넘겼으면 `'all'`, 하나씩 골라 넘겼으면 `'individual'`. 문서와 GA `consent_submit {review, via}` 둘 다(🔒). `consent_view`는 화면이 뜰 때.
- **계정 관리 >**: 프로필의 로그아웃·탈퇴를 그대로 쓴다 — 확인 창 `features/profile/components/profile-screen-view.tsx`, 처리 `features/learner/provider.tsx`의 `signOut`·`deleteAccount`.
- 로그아웃·탈퇴 때 `clearLocalConsent(accountKey)`.
- 서버 `saveConsent` 본문: 전이 규칙(약속 파일 §1 주석) — 시각은 서버가 찍고, 같은 선택 재전송은 시각을 안 바꾼다.
- **방침** `public/privacy/index.html`: `:50` "서버에 저장하지 않습니다" → 계정 보관(직접 삭제·탈퇴까지), 검토본 30일 · `:69` "그 밖의 서비스 이용에는 제한이 없습니다" → 필수 동의 없으면 앱을 쓸 수 없다는 사실로(🔒 기윤이 위험 표시 알고 정함) · `:37`과 어긋남도 맞춘다. 업로드 문구 `photo-upload-view.tsx:81`도.
- 스토어 신고(구글 데이터 안전·애플 개인정보 라벨)는 콘솔 일이라 기윤 몫 — 1줄은 **바꿀 답 목록**을 보고서에 적는다.

**안 하는 것:** 검토 동의를 끄는 스위치(제출 전에 기윤이 정한다 — STATUS 「제출 전 확인」). 사진 화면에서 다시 묻기(필수 안 하면 앱에 못 들어오니 그 경우가 없다).

**끝 확인:** 시뮬레이터에서 새 계정 → 온보딩 → 동의 화면 → [다음] → 홈. 필수 하나 빼면 [다음]이 안 눌림. 앱 끄고 다시 켜면 안 뜸. Firestore `users/{accountKey}/private/consent`에 세 칸·`via`가 찍힘.

## 2줄 — 서버 저장

**전제(기윤 콘솔, 2줄 시작 전):** Firebase Storage가 켜져 있고 기본 버킷 `dasida-app.firebasestorage.app`의 위치를 안다. 버킷 `review/` 30일 수명 규칙은 콘솔에서(2줄은 규칙 문구만 보고서에).

**만드는 것:**
- `savePhotoNote` 본문 — 약속 파일 「저장 규칙」 ①~④ 그대로(동의 403 · 410 · 같은 내용 200 alreadyStored · 다른 내용 409 · 경로 메타 409 · 사진 먼저, 실패면 문서 안 씀). 비교는 `canonicalNoteJson`, 서버 문서에선 서버 전용 칸을 먼저 뗀다.
- 앱: 노트가 뜰 때 축소본(`downscaleToDataUrl` 결과 — 지금은 `use-photo-flow.ts` `start()` 안에서 버려진다, ref로 들고 간다)과 노트를 `savePhotoNote`로. `PhotoNote.submissionId`를 새 노트에 넣는다(옛 노트엔 안 지어낸다). 성공 응답의 `storedAt`을 로컬 노트 `cloudStoredAt`에.
- 노트 카드 ☁ 줄 — 입력은 약속 파일 `CloudNoteState`: 「저장됨」·「저장됨 · 사진 없음」·「저장 중」·「저장 못 함」. 로컬 저장 성공은 증거가 아니다 — 서버 응답으로만.
- 검토본 — `analyzePhoto`에서 조건(authVerified ∧ 검토 동의 ∧ submissionId) 맞으면 받은 축소본을 `reviewPhotoPath`로, 응답 전에. 원장에 `PhotoRunConsentFields`. **분석 자체는 동의로 막지 않는다**(1.0.9·1.0.10·웹이 같은 함수를 쓴다).
- 탈퇴 — 약속 파일 §6 순서(consent 먼저 → 원장에서 검토본 경로 모음 → Firestore·원장 → Storage). Storage 일부 실패 = 탈퇴 실패.

**끝 확인:** 시뮬레이터(동의 끝난 계정)로 사진 한 장 → 노트 → ☁ 「저장됨」 → Firestore `users/{accountKey}/photoNotes/{noteId}` + Storage `photo-notes/…jpg`. 같은 요청 다시 → `alreadyStored`. 1.0.10 앱처럼 동의 문서 없는 요청으로 `analyzePhoto`가 지금과 같은 응답(테스트).

## 3줄 — 다른 기기 보기 (읽기 쪽)

**만드는 것:**
- `listPhotoNotes` 본문 — `users/{accountKey}/photoNotes`를 `createdAt` 내림차순, `before` 커서·`limit`, **`deletedAt` 있는 것도 준다.**
- `getPhotoNoteImage` 본문 — 문서의 `photoPath`를 서버가 읽어 JPEG 바이트(`Cache-Control: private, no-store`), 사진 없으면 404 `PHOTO_MISSING`. 앱이 경로를 보내지 않는다.
- 앱 `remote-note-store.ts` — 목록 읽기 + 사진 내려받기(같은 인증 헤더, `features/learning/firebase-learning-history-api.ts`의 `createRemoteAuthHeaders` 방식). 내려받은 사진은 문서 폴더에 같은 파일명 규칙(`safeNoteFileStem`)으로.
- 지난 노트 화면 `photo-notes-screen.tsx` — 로컬 + 서버를 id로 합친다. 같은 id면 로컬 우선. 서버 실패·오프라인 = 로컬만(오류 띠 없음). `deletedAt` 있는 건 안 그린다. **복원하며 복습 과제를 다시 만들지 않는다.** 서버 노트는 `toLocalNote`로 폰 모양으로.

**안 하는 것:** 「서버에 없는 노트 올리기」 버튼 — 2줄 저장이 main에 들어간 뒤 통합 Claude가 붙인다(4). 자동 동기화·충돌 해결·삭제 UI.

**끝 확인:** 2줄이 아직 없으면 Firestore 콘솔에 테스트 문서를 손으로 하나 넣거나(기윤 계정·집계 제외 기록) 함수 테스트로. 두 기기 확인은 합친 뒤 통합 단계에서.
