## 왜 0칸인가 — 실패가 아니라 차단이다

곱셈 처방은 **09.16에 "반박이 못 깼다"며 통과한 것**이다. 그때 검산 범위가
`A 2~9 양수 × B 끝자리 0 제외`뿐이었다(`docs/weakness-fill-sequence-2026-09-16.md:55`).

이번 반례 둘은 **그 범위 밖**이다. 즉 **"522/522 걸림"은 반례가 들어갈 수 없는 판에서 낸 숫자였다.**

> v1 흐름이었으면 이 처방은 코드에 들어갔다. (Fable)

그러니 이번 판 성적은 `8회 → 0칸`이 아니라 **`8회 → 0칸 + 틀린 처방 1건 차단`**이다.

⚠️ 단 "v1이었다면 반드시 들어갔다"는 **반사실적 추정**이다 (astra).

⚠️ **`primaryWeaknessId`만 비워도 소용없다.** 카드가 `weaknessIds`로 이름표를 그린다
(`photo-note-card.tsx:65-69`). 후보가 둘이면 `"A 또는 B"`로 둘 다 뜬다.

**말풍선(후보가 여럿일 때 학생에게 고르게 하는 것)이 있어야 넣을 수 있다.** 08.11에 🔒 정해졌고

## ⬜ 곱셈 — 보류

`g3_seq_sum_multiply_slip` · 어림 대조 처방
("뒤 수를 10의 배수로 올려 한 번 더 곱하고, 두 값의 차를 `앞 수 × 올린 칸수`와 대본다")

### 세 번 깨진 내력

| | 무엇이 깨졌나 |
|---|---|
| 09.16 검산 | **통과** — 단 범위가 `A 2~9 양수 × B 끝자리 0 제외`뿐 |
| 1차 검산 | **깨짐** — 처방 반례 2건. ① 뒤 수가 이미 10의 배수면 검사 안 됨(34,200건 통과) ② 앞 수가 음수면 "올린 쪽이 크다"가 거짓(1,539쌍 전부) |
| 1차 고쳐쓰기 | 처방 고침. 반례 ①②는 **실제로 막혔다**(코드 확인) |
| 2차 검산 | **깨짐** — 처방이 아니라 **설명 2건이 거짓**. `정확히 ~가 된다`를 무조건으로 씀 |
| 2차 고쳐쓰기 | 🔓 **기윤이 규칙을 한 번 열어줌.** 같은 모양이 여섯 군데라 여섯 다 고침 |
| 3차 검산 | **깨짐** — 여섯 중 다섯은 참, **하나가 또 거짓**. `올린 줄에서 또 흘리더라도 대조가 돌아요` |

### 🔑 진짜 원인 — 문장이 아니라 구조였다

astra가 수식으로 짚고 Fable이 코드로 확인했다.

```
두 계산을  x = A·B + e₁ ,  y = A·T + e₂  라 하면
y − x = A(T − B)  가 성립하는 조건은   e₁ = e₂
```

**둘 다 정답이어야 하는 게 아니다. 두 오차가 같기만 하면 통과한다.**

Fable 실측 — `A −9~9 × B −99~99 × 오차 각 −50~50` **1,428,840쌍**에서
통과 **68,040건이 전부 `e₁ = e₂`**. `e₁ ≠ e₂`인 통과는 **0건**.

> 이 대조는 **"두 줄이 다르게 틀렸을 때만"** 잡는다. 같은 학생이 같은 버릇(0 하나 빼먹기)으로
> 두 번 틀리면 정확히 그 경우를 놓친다. **버릇 잡는 처방이 버릇에 제일 약한 구조다.** (Fable)

**`calc_slip`은 "알고도 손이 미끄러지는" 습관성 실수다.** 그런데 이 검사법은 습관에 제일 약하다.
**처방과 대상이 어긋나 있었다.** 세 번 고쳐도 안 된 이유가 이것이다 — 고칠 자리가 문장이 아니었다.

### 판정 (Fable 최종)

- **4차 고쳐쓰기 안 한다.** 표현만 고치면 같은 자리에서 또 깨진다
- **곱셈 칸은 오늘 보류.** 빈 것 = 0
- **다음 후보는 "부분곱을 적는 절차"** — `9×47`을 `9×40=360`, `9×7=63`으로 따로 적고 합치기.
  "모든 오류를 잡는다"는 주장 대신 **자리값·받아올림을 종이에 드러내는 동작**을 가르치는 방향.
  ⚠️ 이것도 검증된 처방이 아니다. 새 후보로 검산받아야 한다

### 다시 만들 때 반드시 적을 것

**"두 줄이 같은 만큼 틀리면 못 잡는다"** — 이 조건을 적고, **적은 뒤에 처방으로서 값이 얼마 남나를
먼저 본다.** (Fable)
