# 사진 flow '오류 짚기' 설계 — 물어보는 앱에서 짚어주는 앱으로

- 날짜: 2026-07-25
- 범위: web-proto 사진 flow 전체 (앱 코드는 한 글자도 건드리지 않음)
- 목표: 커뮤(오르비 등) 공개 가능한 품질
- 상태: 설계 승인 완료 (섹션 1~6 전부 기윤 승인)

## 0. 배경과 문제

현재 사진 flow는 AI가 풀이를 읽고 방법까지 맞힌 뒤, 정작 진단은 "어디가 가장
어려웠나요? ①②③" 설문(자기 신고)으로 한다. 두 가지가 어긋난다.

1. **자기 신고의 모순**: 학생은 자기가 어디서 틀렸는지 모르는 사람이다. 알면
   다시다가 필요 없다. 분석은 AI의 일이다.
2. **통조림 어긋남**: 설문·설명이 앱 챌린지 문제(f(x)=x²−10x+29) 기준으로
   써져 있어, 임의의 사진 문제와 내용이 어긋난다 ("4를 더하고 빼는", "최솟값").

전환 방향 🔒: **AI가 직접 "여기서 틀렸네. 맞아?"라고 짚는다.**
학생에게 넘기는 것은 분석이 아니라 느낌 증언뿐이다.

원칙: **살은 생성, 뼈는 고정.** 대화 구조·약점 분류·안전망은 사람이 설계하고,
그 안에 들어가는 내용(짚는 지점·설명·확인 문제)만 AI가 그 자리에서 생성한다.

## 1. 약점 분류 체계 v2

약점 카드 = **방법(methodId) × 실수 유형(6종 중 1) × 증거(학생 풀이에서 인용한 줄)**

주제 축은 별도로 두지 않는다 — 방법이 확정되면 주제는 자동으로 따라온다.

### 실수 유형 6종 (문제 푸는 여정 순서)

| # | id | 이름 | 정의 | 예시 |
|---|----|------|------|------|
| 1 | `concept_gap` | 개념 구멍 | 원리 자체를 모르거나 잘못 앎 | 판별식이 왜 근의 개수를 알려주는지 모름 |
| 2 | `formula_recall` | 공식 기억 | 공식·패턴을 잘못 외움 | 근의 공식 −b를 +b로 씀 |
| 3 | `setup_error` | 식 세우기 | 문제→식 번역에서 틀림 | "3년 후 나이"를 3x로 세움 |
| 4 | `calc_slip` | 계산 손실수 | 알고도 손이 틀림 (부호·약분·산술) | √20/2를 2√5로 씀 |
| 5 | `procedure_miss` | 절차·조건 누락 | 순서 꼬임, 조건·경우 빼먹음 | 제곱 후 검산 안 함 |
| 6 | `answer_read` | 마무리 해석 | 다 풀고 마지막에 답을 잘못 읽음 | x 구했는데 문제는 x² |

- AI는 이 6종 중 하나를 **반드시** 고른다 (스키마 enum 강제, 7번째 발명·"글쎄" 불가).
- 설명문(자유 서술)과 분류 도장(객관식)을 분리: 표현력과 통계를 둘 다 잡는다.
- 데이터가 쌓이면 "네 실수의 70%가 calc_slip" 같은 말이 가능해진다.

### 기존 59종과의 관계

- 기존 weaknessId 59종은 앱(모의고사) 전용으로 그대로 둔다. **마이그레이션 없음**
  (web-proto는 로그인이 없어 앱 학습 기록에 쓰지 않는다).
- 구→신 매핑 (앱 이식 시점에 사용할 부록):
  - `calc_repeated_error`, `expansion_sign_error`, `coefficient_sign_confusion` → `calc_slip`
  - `basic_concept_needed`, `formula_understanding` → `concept_gap`
  - `quadratic_formula_memorization`, `factoring_pattern_recall`, `vertex_formula_memorization` → `formula_recall`
  - `g2_eq_setup` → `setup_error`
  - `solving_order_confusion`, `counting_overcounting` → `procedure_miss`
  - `min_value_read_confusion`, `max_min_judgement_confusion` → `answer_read`
  - `g1~g3_*` 주제 태그 → 방법 축이 대신함

## 2. analyzePhoto 확장 — 원샷 생성

생성 시점은 **원샷**: 기존 analyzePhoto 호출 하나에서 전부 미리 생성해 웹이
"주머니"에 보관한다. 새 엔드포인트 없음(공격 표면·비용 가드 그대로), 학생이
기다리는 건 업로드 직후 한 번뿐.

쪽지(프롬프트)의 질문 7개:

1. 무슨 방법으로 풀었어? (기존)
2. 풀이 옮겨 적어줘 (기존, transcription)
3. **어느 줄에서 틀렸어?** — 자신 있는 순서로 **최대 2군데**, 학생이 실제 쓴 줄 인용.
   확실한 게 하나뿐이면 하나만 (억지 2등 금지)
4. **왜 틀렸어?** — 후보마다 학생 눈높이 2~3문장 + 탓하지 않는 한 줄
5. **실수 유형 도장** — 후보마다 6종 중 1개
6. **확인 문제(쪽지시험)** — 후보마다 객관식 1개(보기 3), 방금 짚은 그 조각만
7. **오류 짚기 자신감** — 0~1 (방법 자신감과 별개의 저울)

- 웹의 검문소: 자신감 < 문턱이거나 3~6번이 비면 → 조용히 안전망으로.
  AI가 "못 찾겠다"고 말할 길을 열어둔다 (억지 짚기보다 설문이 낫다).
- 문턱 숫자는 나사다: 처음엔 낮게 잡고 채점표 데이터로 조인다.
- 방법 판별의 기존 문턱 0.74와 같은 방식 (AI 자기 채점 + 웹은 비교만).
- 비용: 이미지 토큰(비싼 부분)은 이미 지불 중. 증가분은 출력 몇 줄 = 호출당
  소수점 원 수준.

## 3. 웹 사다리 — 경우 1·2·3 전체

### 공통 규칙

- **주머니 유효 규칙**: 최종 확정된 방법 == 주머니를 만든 방법(1등 추측) → 짚기.
  다르면 → 주머니 폐기 → 느낌 설문.
- **투 스트라이크**: 짚기는 최대 2번. 두 번 헛짚으면 교대 (세 번째 시도 없음).
- **분석 숙제 금지**: 학생에게 "어디서 틀렸어?"(분석)를 넘기지 않는다.
  설문은 "풀면서 느낌상 뭐가 걸렸어?"(경험 증언)로만 묻는다.
  풀이 줄 버튼으로 학생이 직접 짚게 하는 안은 **폐기** (기윤 결정).
- 어느 문에서 거절당해도 종착지는 항상 약점 카드 (막다른 길 없음).

### 경우 1 — 방법 확신 (확신도 ≥ 0.74) · 가지 6개 전부 확정

| 가지 | 경로 | 결말 |
|---|---|---|
| 1 | "맞아" → 1번 짚기 적중 | 왜 설명 → 쪽지시험 → 카드 🎯 |
| 2 | 1번❌ → 2번❌ | 느낌 설문 → 카드 |
| 3 | 1번❌ → 2번 적중 | 왜 설명 → 쪽지시험 → 카드 🎯 |
| 4 | 1번❌ → 2번 후보 없음 | 느낌 설문 → 카드 |
| 5 | 방법 뒤집힘("아니야, 다른 방법") | 후보 카드(기존 사다리·excludeIds) → 느낌 설문 → 카드 |
| 6 | 방법 맞는데 오류 자신감 부족 | **B안**: "과정에서는 틀린 데를 못 찾았어. 과정은 맞게 간 것 같거든 — 이러면 보통 마지막 답이나 검산에서 새는 경우가 많아" + 힌트 실은 설문 |

대표 멘트 (확정 문안):

- 1번 짚기: "여기 — √20을 2로 나눠서 2√5로 쓴 부분. 여기서 틀린 것 같아. 맞아?"
  (실제 쓴 줄 인용 + 말끝은 "~같아. 맞아?"로 탈출구)
- 2번 짚기: "그래? 그럼 **하나 더 걸리는 데가 있었는데** — …. 여기 아니야?"
  (미리 봐뒀다는 뉘앙스, 찍기 느낌 방지)
- 짚기 전부 실패: "음, 그럼 내 눈에 보이는 데는 아니었나 보네. 각도를 바꿔보자 —
  풀면서 느낌상 뭐가 제일 걸렸어?"
- 짚기 거절 시 변명 금지: "그래? 내가 잘못 짚었네" 한 마디로 접는다.
- 쪽지시험 틀림: 한 번만 더 짚고 넘어감 (재시험 없음). 결과는 카드에 기록
  (통과 → "원리는 잡았어" / 실패 → "원리부터 한 번 더").

### 경우 2 — 방법 애매 (중간 확신) · 확정

1층 입구만 다르고 2층(짚기·설명·쪽지시험·카드)은 경우 1 전부 재사용.

- 확신 중간: **추측 확인** — "풀이에 '…' 쓴 게 보이던데, 근의 공식으로 푼 것
  같아. 맞아?" → 맞아 → 주머니 유효 → 2층 진입 / 아니야 → 후보 버튼(1등
  제외) → 느낌 설문 → 카드
- 확신 낮음: 바로 보기 제시 — 학생이 고른 게 우연히 1등 추측과 같으면 주머니
  살아남 → 2층 진입 (공짜 기회)
- "맞아" 클릭은 확신도 문턱 조정용 채점표 데이터가 된다.

### 경우 3 — 풀이 흔적 없음 · 확정

짚을 재료가 없으므로 2층 불가. 설문이 폴백이 아니라 정당한 본선.

- 첫 멘트에 **다시 찍기 유도** 추가 (신규 결정): "혹시 종이에 풀었으면, 풀이까지
  나오게 다시 찍어줄래? 그러면 어디서 틀렸는지 내가 직접 짚어줄 수 있어.
  머리로 푼 거면 괜찮아 — 어떤 방법으로 풀었는지 짧게만 알려줘."
  [📷 다시 찍기] [✏️ 직접 입력]
- 다시 찍기 → 새 사진 분석 → 경우 1/2로 승격 (비용: 버튼은 0, 재분석 시 vision 1회)
- 직접 입력 → 기존 사다리(diagnoseMethod 판별 → 후보 → 전체 목록) 그대로,
  끝만 느낌 설문 → 카드로 교체. "잘 모르겠어"면 방법 없이 일반형 설문 → 카드.

## 4. 조교 규칙서 (10개조)

analyzePhoto 시스템 프롬프트에 들어갈 규칙. 강제 가능한 것(4·5번 등)은
프롬프트에만 맡기지 않고 스키마 검증으로 이중 잠금.

**인용**
1. 학생이 실제로 쓴 줄만 인용해라. 사진에 없는 식을 지어내면 끝이다.
2. 오류 후보는 자신 있는 순서로 최대 2개. 확실한 게 하나면 하나만.
3. 여러 군데 틀렸어도 한 번에 하나만 짚어라 (제일 결정적인 것부터).

**분류**
4. 실수 유형은 6종 중 하나만 (enum 강제).
5. 자신 없으면 자신감 숫자를 낮게 써라. "못 찾겠다"가 억지 짚기보다 낫다.

**내용**
6. 정답·최종 값을 알려주지 마라. 틀린 이유까지만.
7. 새로운 풀이 방법을 제안하지 마라. 학생이 쓴 방법 안에서만.
8. 쪽지시험은 방금 짚은 그 한 조각만, 보기 3개.

**말투**
9. 왜 설명은 2~3문장 + 탓하지 않는 한 줄. 반말 코치 톤, 다그침 금지.

**예시**
10. 동봉된 앱 진단 예시는 모양 참고용이다. 말투·깊이·구조만 따라 하고,
    예시 속 숫자·식·내용을 절대 가져다 쓰지 마라.

### 규칙 10의 3종 세트 (프롬프트에 실제 포함)

- **모범 예시 블록** (고정 1~2개, 앱의 검증된 진단에서 발췌):
  챌린지 문제(f(x)=x²−10x+29)의 완전제곱식 진단 — 질문·보기·설명 톤.
- **❌/⭕ 대조 쌍**:
  - ❌ "4를 더하고 빼는 원리가 헷갈렸구나" (예시 내용이 새어 들어옴)
  - ⭕ "√20을 2로 나눌 때 반으로 줄이는 대신 2를 곱했어" (모양만, 내용은 학생 사진에서)
- 방법별 예시 골라 붙이기는 V1 제외 (확장 지점).

## 5. 느낌 설문 재작성

안전망 설문을 일반형으로 재작성. 원칙 5개:

1. 특정 문제의 숫자·식·상황 금지 (어떤 문제가 와도 성립)
2. 보기 하나 = 실수 유형 6종 중 하나 (카드 언어로 곧장 번역)
3. 방법마다 그 방법에서 나올 법한 유형 3개 선별 + "잘 모르겠어"
4. 분석 말고 느낌: "어디서 틀렸어?" ❌ → "뭐가 걸렸어?" ⭕
5. 반말 코치 톤 (짚기 멘트와 같은 목소리)

대표 예시:

- 근의 공식: 공식이 가물가물했어(`formula_recall`) / 대입하고 계산하다가
  어수선해졌어(`calc_slip`) / 마지막에 답을 어떻게 쓸지 헷갈렸어(`answer_read`)
- 완전제곱식: (x−a)² 꼴 원리가 헷갈렸어(`concept_gap`) / 식 변형하다
  미끄러졌어(`calc_slip`) / (x−a)²=k 다음 뭘 할지 몰랐어(`procedure_miss`)
- 극한: 쪼개는 개념이 안 잡혔어(`concept_gap`) / 식 정리가 엉켰어(`calc_slip`) /
  수렴·발산 마지막 판단이 헷갈렸어(`answer_read`)

추가 통조림: **유형 6종 × 일반형 처방 한 줄** (설문 경로 카드의 마지막 줄용).
짚기 성공 시엔 AI가 학생 맞춤 처방을 생성.

작업 방식: 31개 방법 × 3보기(총 93문장) + 처방 6줄은 구현 단계에서 Claude가
전체 초안 → 기윤 검수.

## 6. 검증 기준

### 1겹 — 기계 검증 (자동)
- 기존 테스트(69개) + 신규 스키마 테스트 통과
- 6종 enum·자신감 범위 강제 확인 (위반 시 접수 거부)
- 폴백 무결성: 생성 필드 결손 시 모든 가지에서 설문으로 조용히 착지 (일부러 깨서 확인)
- 비용 가드 불변 (이미지 상한, maxInstances 3 × concurrency 5, 더블클릭 방지)

### 2겹 — 경로 검증 (브라우저 E2E)
설계도의 모든 문을 한 번씩 연다: 경우 1 가지 6개, 경우 2 추측 확인·지하 1층,
경우 3 다시 찍기·직접 입력.

### 3겹 — 품질 검증 (기윤 주도)
시험지 10장: 실수 유형을 골고루 심은 손글씨 오답 사진
(calc_slip 3 / formula_recall 2 / concept_gap 2 / answer_read 2 / procedure_miss 1).
정답지를 아는 시험이므로 채점 가능.

| 항목 | 기준 | 성격 |
|---|---|---|
| 1번 짚기 적중 | 7/10 이상 | 목표선 (미달 시 프롬프트 조정) |

## 7. 확장 지점 (V1 제외, 데이터로 판단)
