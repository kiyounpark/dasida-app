# 즉석 재도전 + 개인화 망각곡선 엔딩 (web-proto)

- 날짜: 2026-07-25
- 대상: `web-proto` 오류 짚기 사다리의 엔딩 구간
- 상태: 기획중

## 배경 / 문제

현재 사다리는 약점 카드 이후 "다음에 같은 자리에서 안 틀리게, 앱에서 이어서 잡아줄게"라는
약속(IOU)으로 끝난다. 진단은 있는데 갚는 장면이 없다. 학생이 만족을 느끼는 순간은
"내 약점을 알았다"가 아니라 **"아까 무너진 그 자리를 이번엔 통과했다"**인데,
체험에 그 장면이 없다.

목표: 체험 안에서 즉석 재도전으로 성공 장면을 완결하고, 간격 복습은
개인화 망각곡선 화면으로 "왜 앱이 필요한가"를 설득한 뒤 앱 전환(CTA)으로 잇는다.

## 확정된 결정

### 1. 재도전 형태 — 틀린 자리만 재밟기

쌍둥이 문제 통째(B)나 빈칸 채우기(C)가 아니라, **아까 틀렸던 그 단계 직전까지
세팅된 상황을 주고 "여기서 다음 한 수는?"만 객관식 1문항**으로 묻는다.

- 핵심 감각: "같은 자리, 이번엔 통과." 문제 하나 더 푸는 성취감(B)은
  앱의 간격 복습 몫으로 남긴다.
- 데이터: **analyzePhoto 원샷 응답에 AI가 생성** (2026-07-25 개정 — 프로토는 실제 AI
  분석으로 돌아가므로 정적 데이터 불가. 쪽지시험과 같은 방식으로 원샷에 필드 추가).
  `errorCandidates[i]`에 선택(optional) 필드 4개:
  - `retrySetup` — 직전까지 세팅된 쌍둥이 상황 서술
  - `retryPrompt` — "여기서 다음 한 수는?"
  - `retryOptions` (정확히 3개) / `retryAnswerIndex` (0~2)
- 생성 시점 vs 노출 시점 분리: 생성은 사진 분석 원샷에서 미리, 노출은 학생이
  방법·오류 지점에 **두 번 동의한 뒤**(aiConfirmed 경로)에만. 동의 없으면 안 꺼냄.
- 위치: 약점 카드 직후. "그럼 바로 확인해보자 — 같은 자리 하나 더" 식으로 진입.
- 탈출구: "지금은 넘어갈래" ghost 버튼 → 재도전 건너뛰고 곡선으로. 재도전은
  관문이 아니라 보너스 문제 — 어느 선택이든 곡선으로 착지, 막다른 길 없음.
- 쪽지시험(showCheck: 원리 이해 확인)과 역할이 다름 — 재도전은 새 상황에 적용.

#### 안전장치 (3중)

1. **조교 규칙서 조항 추가** — "재도전 문제는 학생이 틀린 그 단계만, 같은 원리,
   숫자만 바꿔서, 보기 3개. 새 개념 금지." 범위를 좁혀 엉뚱한 생성을 줄인다.
2. **정화 확장** — `sanitizeErrorCandidates`에 retry 필드 검증 추가. 단, retry가
   불량이어도 **후보 자체는 살린다** (retry 필드만 제거 → 짚기·쪽지시험은 정상 진행).
3. **if 관문 (웹)** — retry 필드가 없으면 재도전을 조용히 건너뛰고 곡선으로 착지.
   상류(오류 짚기 브랜치·구버전 functions)가 어떻게 변해도 체험이 깨지지 않는다.
   남는 위험(그럴듯한데 정답 키가 틀린 문제)은 출시 전 실사진 시식 테스트로 확인 —
   문항 1개짜리 구조라 피해 범위는 작다.

### 2. 재도전 실패 시 — 한 번 짚고, 실패를 앱 예고로 전환

- 정답과 원리를 한 줄로 짚어주고 끝. 재시도 없음 ("재시험 없음, 늘어지면 귀찮음 축 침범" 원칙 유지).
- 코치 연결 대사: "지금 바로 또 푸는 것보다, 하루 이틀 뒤에 다시 만나는 게 진짜 붙는 방법이야 — 그걸 앱이 해줘."
- 구조상 어느 엔딩이든 예고편이 성립: 성공 → "이걸 유지시켜주는 게 앱",
  실패 → "이걸 잡아주는 게 앱".

### 3. 설문 경로(aiConfirmed=false) — 재도전 없음

- "아까 틀린 그 자리"가 특정되지 않으므로 재도전이 성립하지 않는다. 억지 일반 문제(유형별 대표 문제)는 내지 않는다.
- 대신 곡선 화면의 예고 문구를 변형: "네가 짚어준 이 약점, 앱에서는 문제로 만들어서 다시 물어봐 줄게."
- 경로별 체험 밀도 차이는 의도된 것 — 풀이 사진을 제대로 찍을 동기가 된다.

### 4. 엔딩 — 개인화 망각곡선 화면 (예고 카드 역할 흡수)

일반 에빙하우스 곡선(학원 설명회 클리셰)이 아니라, **방금 잡은 약점을 곡선 위에 얹는다**:

- 곡선 시작점 라벨: "방금 잡은 자리 — {방법} × {실수 유형} (지금 100%)"
- 하락 구간 마커: "내일이면 여기쯤 — 절반은 사라져"
- 알림 마커: "🔔 그 직전에 내가 다시 물어볼게"
- 코치 대사: "이건 네 의지 문제가 아니라 뇌가 원래 이래. 그래서 타이밍은 내가 챙길게."
- 구현: SVG 정적 렌더링. 별도 예고 카드는 만들지 않는다(곡선 화면이 그 역할).
- 문구 변형 3종: 재도전 성공 / 재도전 실패 / 설문 경로.

### 5. CTA — 다운로드 버튼 추가

엔딩 액션 버튼 2개:

- `📱 다시다에서 이어서 하기` — 스토어 링크 (양대 스토어 라이브)
- `다른 문제도 올려보기` — 기존 리셋 동작 유지

## 흐름 (변경 후)

```
showCheck (쪽지시험)
  → showWeaknessCard (약점 카드, 기존 유지)
  → [aiConfirmed && retry 필드 존재] startRetry (즉석 재도전, 객관식 1문항)
      → 성공: "그 자리, 이번엔 통과" 멘트
      → 실패: 정답+원리 한 줄 (재시도 없음)
      → 넘어갈래: 그대로 통과
  → showForgettingCurve (variant: success | fail | survey)
  → CTA 버튼 2개
```

retry 필드가 없으면(구버전 응답, 정화 탈락, AI 미생성) startRetry는 건너뛰고
바로 곡선으로 — 이때 variant는 survey가 아니라 경로에 맞는 기본값을 쓴다.

설문 경로는 약점 카드 → 곡선(survey variant) → CTA로 직행.
기존 엔딩 대사 "오늘 여기까지…앱에서 이어서 잡아줄게"는 곡선 화면으로 대체.

## 하지 않는 것 (Non-goals)

- 실제 알림 발송, 실제 간격 복습 스케줄링 (앱 본편 몫)
- 재도전용 별도 AI 호출 (기존 원샷에 필드만 추가 — 호출 수·대기 시간 불변)
- 힌트 재시도, 유형별 일반 재도전 문제, 재도전 강제(관문화)

## 열린 질문

- 스토어 링크 URL: iOS/Android 분기 처리 vs 스마트 링크(원링크) — 구현 시 확정

## 검증 시나리오 (수동)

1. 재도전 성공 경로: 짚기 → 쪽지시험 → 약점 카드 → 재도전 정답 → success 곡선 → CTA
2. 재도전 실패 경로: 재도전 오답 → 정답 한 줄 → fail 곡선 → CTA
3. 넘어갈래 경로: 재도전 화면에서 스킵 → 곡선 → CTA
4. 설문 경로: 설문 착지 → 약점 카드 → survey 곡선(재도전 없음) → CTA
5. retry 필드 결손: 필드 없는 응답에서 재도전 없이 곡선 착지 (에러 없음)
6. 곡선 SVG에 방법×유형 라벨이 실제 데이터로 렌더링되는지 확인
7. 실사진 시식: 실제 풀이 사진 여러 장으로 재도전 문제 품질(정답 키 포함) 육안 확인
