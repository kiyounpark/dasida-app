# 09.26 — 계산 실수를 절반 넘게 놓친다 → 검산 칸 — astra·Fable

> 부른 법은 `docs/how-we-decide.md` 그대로. astra = `codex exec` gpt-6-astra(stderr `model:` 확인), Fable = Agent `model: "fable"`.

## 계기 — 측정 (로컬 에뮬레이터, 같은 사진 20회)

25−12=11 사진: 옛 프롬프트 4/10, 개념 설명 붙은 새 프롬프트 4/10(누적 8/20). 놓친 12회는 전부 reasoning 181~516 토큰·3~6초,
잡은 8회는 922~2,156 토큰·10~22초 — 겹치지 않는다. 놓친 회차 transcription은 전부 "11"을 제대로 읽었다("25-12를 계산해 11로 적은 뒤…") → **오독이 아니라 검산을 건너뜀**.
프롬프트엔 이미 "속으로 반드시 검산하세요"가 있었다.

Claude가 확인한 것: `analyze-photo.ts:28` "high는 … 적중률이 medium과 같아" 주석의 근거(b988e1a)는 **인수분해 실수 사진 1장 × 3회, 둘 다 3/3 천장** — 계산 실수엔 측정된 적 없었다.

## 구현

`PHOTO_ANALYSIS_SCHEMA.lineChecks: [{line, recomputed, ok}]`(최대 8, transcription 바로 뒤). 프롬프트: "속으로 검산" → 검산표를 errorCandidates 전에 먼저 채우게, 학생 값 베끼지 말 것, 애매하면 ok:true로 짚지 말 것.
학생에겐 안 나간다 — `analyze-photo.ts` zod가 모르는 키를 버리고 `buildPhotoRouterResult`도 필드를 골라 싣는다(테스트로 잠금). 원장은 요약만이라 무관.
