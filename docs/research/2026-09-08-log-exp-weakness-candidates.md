# 지수·로그 약점 이름표 — 아침에 ⭕❌ 칠 목록

2026.09.08 밤 작성. 판정은 기윤이 한다. 이 문서는 재료다.
(같은 자리에 있던 1차 문서는 이 문서가 대신한다. 1차 후보 5개는 아래 후보 목록에 다 들어와 있다.)

읽는 법: **2번만 보면 된다.** 후보마다 ⭕ 또는 ❌ 를 치면 끝. 1번과 6번은 그다음에 봐도 된다.

용어 세 줄:
- **약점 이름표** = 오답노트 카드 맨 아래 🏷️ 줄에 뜨는 한국어 이름. 지금 지수·로그엔 "지수·로그 계산" 하나.
- **실수유형** = 6종. 개념 구멍 / 공식 기억 / 식 세우기 / 계산 손실수 / 절차 누락 / 마무리 해석.
- 약점 하나는 유형 하나만 커버한다(1:1). 그래서 지수·로그 6칸을 채우려면 이름이 6개 필요하다.

---

## 1. 한 줄 결론

**새 이름표는 2~4장으로 보인다.**

- 4가지 방식이 후보 22개를 냈고, 적대적 검증에서 5개가 살아남았다.
  그중 **네 방식이 전원 같은 곳에 도착한 게 2개**, 3/4가 1개다. 나머지는 한 방식만 냈거나 태그가 다툰다.
- 바닥이 2인 이유 — 전원 합의 2개는 서로 다른 문제에서 출발해 같은 자리에 도착했다.
- 천장이 4인 이유 — 이름 1장 = **손으로 쓰는 파일 12개**다(8월 38351be를 `git show --stat`으로 셌다). 5장이면 60개.
- **0장도 선택지다.** 바로 아래 것만 해도 오늘 화면이 바뀐다.

### 먼저 — 배경 하나가 틀렸다

"서버가 `g3_log_exp_base`라는 이름을 몰라서 못 붙인다"는 **소스 기준으로 틀렸다.**

`functions/src/learning-history.ts`를 열어봤다. `weaknessOrder` 배열에 `'g3_log_exp_base'`가 있고,
라벨 목록에도 `g3_log_exp_base: '지수법칙·밑 통일 오류'`가 그대로 있다.
`git log 38351be..HEAD -- functions/` 를 돌렸더니 **커밋 0건** — 1.0.7 되돌리기는 이 파일을 안 건드렸다.

즉 남은 건 `firebase deploy --only functions` 한 번과 `data/diagnosisTree.ts` 한 줄
(`weaknessId: 'g3_log_exp'` → `'g3_log_exp_base'`)이다. 보완 흐름 296줄은 8월에 다 만들어져 있다.

**확인 안 한 것:** 지금 떠 있는 함수에 실제로 배포됐는지. 저장소로는 안 보인다
(`docs/PROGRESS.md`의 functions 배포 기록은 2026.03.19가 마지막).
확인하려면 `recordLearningAttempt`에 `g3_log_exp_base`를 한 번 실어보면 된다. 400이면 아직 안 나간 것.

**단, 이걸 해도 유형 커버는 안 는다.** `g3_log_exp_base`도 공식 기억이라 같은 칸에 이름이 2개가 되고,
카드엔 `지수·로그 계산 또는 지수법칙·밑 통일 오류`로 나란히 뜬다(`photo-note-card.tsx:58`, 봤다).

### 지금 6칸 — 하나 차 있고, 그 하나도 설문에선 안 뜬다

| 실수유형 | 지금 | 학생이 설문에서 고를 수 있나 |
|---|---|---|
| 개념 구멍 | 빈손 | ⭕ 1번 버튼 |
| 공식 기억 | `g3_log_exp` (+휴면 중인 `g3_log_exp_base`) | ❌ 버튼 없음 |
| 식 세우기 | 빈손 | ❌ |
| 계산 손실수 | 빈손 | ⭕ 2번 버튼 |
| 절차 누락 | 빈손 | ❌ |
| 마무리 해석 | 빈손 | ⭕ 3번 버튼 |

전부 직접 봤다. 지수·로그 선택지 3개가 전부 `g3_log_exp`(`diagnosisTree.ts:470-489`),
그 이름과 `g3_log_exp_base` 둘 다 공식 기억(`weakness-mistake-type-map.ts:72-73`),
`log_exp`는 커스텀 설문이 없어 기본 3개를 받는다(`survey-data.js` — 개념·계산·마무리).

**차 있는 칸과 학생이 누를 수 있는 칸이 하나도 안 겹친다 → 설문 경로에서 지수·로그 이름표는 0장 뜬다.**
"6개 중 1개"가 아니라 0이다. 4방식이 전부 따로 발견했고 나도 코드로 확인했다.

앱은 다르다. 앱엔 설문이 없고 AI가 유형을 찍는다(`use-photo-flow.ts:366` `mistakeType: candidate.mistakeType`, 봤다).
그래서 앱에선 AI가 '공식 기억'을 짚을 때만 이름표가 뜬다.

### 후보 1 — 밑 1 미만 부등호 방향 오류
**개념 구멍 칸 · 4방식 전원 합의 · 오늘 설문에 닿는다**

학생 보기: "밑이 1보다 작은 지수·로그 부등식에서 부등호 방향이 헷갈렸어요."

**왜 필요한가 — 식 하나로**

> (1/2)²ˣ < (1/2)ˣ⁺³

밑 1/2는 곱할수록 작아진다(1/2, 1/4, 1/8…). 그래서 지수만 떼어 비교할 때 부등호가 뒤집힌다.

- 정답: 2x > x + 3 → **x > 3**
- 학생: 2x < x + 3 → **x < 3**

정답은 3보다 큰 수 전부, 학생 답은 3보다 작은 수 전부다. **겹치는 수가 하나도 없다.**
(x = 4를 넣어보면 왼쪽 (1/2)⁸ = 1/256, 오른쪽 (1/2)⁷ = 1/128. 왼쪽이 더 작으니 x = 4는 진짜 답이 맞다.)

로그도 같은 자리다. log_(1/3) x > 2 의 정답은 0 < x < 1/9 인데 학생은 x > 9로 쓴다.
(검산: log_(1/3) 9 = −2 라 2보다 작다. x = 9는 답이 아니다.)

**지금 g3_log_exp와 뭐가 다른가**

지수·로그 선택지 3줄 어디에도 '부등식'이라는 말이 없다(`diagnosisTree.ts:474-489`, 봤다).
지금 이 학생이 뭘 골라도 붙는 건 "지수·로그 계산"이고, 처방은
"logₐb + logₐc = logₐ(bc) … 기본 성질을 점검하세요"다(`diagnosisMap.ts:468`, 봤다).
성질을 100% 외워도 부등호 방향은 안 잡힌다. 이건 성질이 아니라 "밑이 1보다 작으면 줄어든다"는 개념이다.

### 후보 2 — 진수·범위 조건 확인 누락
**절차 누락 칸(태그는 아래 갈림길) · 4방식 전원 합의 · 설문엔 버튼 없음**

학생 보기: "답은 구했는데 진수 조건이나 t > 0 확인하는 걸 빼먹었어요."

**왜 필요한가 — 식 하나로**

> log₂(x − 1) + log₂(x − 3) = 3

합은 곱으로 묶인다.

> log₂{(x − 1)(x − 3)} = 3 → (x − 1)(x − 3) = 8 → x² − 4x − 5 = 0 → **x = 5 또는 x = −1**

여기서 멈추면 답이 두 개다. 그런데 x = −1 을 넣으면 log₂(−2) 가 된다.
2를 몇 번 곱해도 음수가 안 나오니 로그 안에는 양수만 들어갈 수 있다. **답은 x = 5 하나다.**

치환 쪽도 같다. 4ˣ − 3·2ˣ − 4 = 0 에서 t = 2ˣ 로 놓으면 t = 4, −1 이 나오는데,
2ˣ 는 절대 음수가 안 되니 t = −1은 버려야 한다.

**지금 g3_log_exp와 뭐가 다른가**

이 학생은 **로그 성질을 한 글자도 안 틀렸다.** 그런데 받는 처방이 "기본 성질을 점검하세요"다 —
이미 맞게 한 걸 다시 시키는 꼴이다. 필요한 건 "구한 답을 원래 식에 넣어보기" 한 동작이다.

**⭕ / ❌** →

### 후보 3 — 치환 후 원래 문자 복귀 누락
**마무리 해석 칸(태그는 아래 갈림길) · 4방식 중 3방식 · 마무리 해석이면 오늘 설문에 닿는다**

학생 보기: "t로 바꿔 풀어놓고 x로 되돌리지 않은 채 답을 썼어요."

**왜 필요한가 — 식 하나로**

> 4ˣ − 5·2ˣ + 4 = 0

4ˣ = (2ˣ)² 이니 t = 2ˣ 로 놓으면 이차방정식이 된다.

> t² − 5t + 4 = 0 → (t − 1)(t − 4) = 0 → t = 1, 4

**여기서 답을 1과 4로 쓰면 틀린다.** 문제가 물은 건 x다.

> 2ˣ = 1 → x = 0 / 2ˣ = 4 → x = 2

근의 합을 묻는 문제면 정답 0 + 2 = **2**, 학생 답 1 + 4 = **5**.

**지금 g3_log_exp와 뭐가 다른가**

`g3_log_exp`와 `g3_log_exp_base`의 생각단계를 다 읽었다(`review-content-map.ts:1903-1976`).
다루는 건 로그 성질·밑 변환·밑 통일뿐이고 **치환은 어느 쪽에도 없다.** 겹칠 데가 없다.

---

#### ⚠️ 후보 2와 3 사이에 기윤이 정할 게 하나 있다

둘 다 "다 풀어놓고 마지막에 틀린" 모양이라 태그가 겹칠 수 있다.
**둘 다 마무리 해석으로 달면 한 칸에 이름 2개**가 되어 카드에 "A 또는 B"로 같이 뜬다.

재료가 지지하는 조합: **후보 3 = 마무리 해석**(문자 그대로 답을 잘못 씀, 설문 3번 버튼에 닿음),
**후보 2 = 절차 누락**(조건 확인 단계를 빼먹음).
저장소에 반대 선례도 있다 — `g2_trig_equation_range`(삼각방정식 범위 오류)는 마무리 해석으로 잡혀 있다.
갈리는 지점은 하나: 삼각 쪽 범위는 **문제에 적혀 있고**, 진수 조건은 학생이 로그의 정의에서 스스로 만들어야 한다.

### 후보 4 — 거듭제곱 수 세기 (8이 2의 몇 제곱인가)
**계산 손실수 칸 · ⚠️ 적대적 검증 안 거침(1차 실행에만 있던 후보) · 오늘 설문에 닿는다**

학생 보기: "방법은 맞게 갔는데 8이 2의 몇 제곱인지에서 미끄러졌어요."

**왜 필요한가 — 식 하나로**

> 4ˣ = 8ˣ⁻¹

8 = 2³ 인데 **2⁴ 로 잘못 세면** 이렇게 된다.

> 2²ˣ = 2⁴ˣ⁻⁴ → 2x = 4x − 4 → **x = 2**

맞게 8 = 2³ 으로 보면:

> 2²ˣ = 2³ˣ⁻³ → 2x = 3x − 3 → **x = 3**

풀이 방법은 처음부터 끝까지 맞았다. 숫자 하나에서 답이 갈렸다.

**지금과 뭐가 다른가 — 이 후보는 저장소 안에 증거가 있다**

`data/review-content-map.ts:1951`에 이 오답이 **이미 들어 있다**(봤다):

> 오답 보기 "4 = 2², 8 = 2⁴ 로 보고 양변을 밑 2로 바꾼다"
> 피드백 "2⁴ 는 16이에요. 8은 2를 세 번 곱한 2³ 이에요."

문제는 그다음이다. 이 오답은 `g3_log_exp_base`에 묶여 있고 그건 **공식 기억**이라
(`weakness-mistake-type-map.ts:73`), 숫자를 잘못 센 학생이 받는 처방이 이거다(`mistake-types.ts:15`):

> 시작 전에 공식을 손으로 세 번 써보자.

공식은 다 맞게 썼는데 공식을 세 번 쓰라고 한다.

**⚠️ 주의:** 이 후보는 4방식 실험에 안 들어가서 적대적 검증을 안 거쳤다.
다만 검증조가 다른 계산 손실수 후보 셋을 죽이면서 각각 이렇게 적었다 —
"진짜 산술 미끄러짐 사례로 근거를 갈아끼우면 다시 볼 값어치가 있다." 이게 정확히 그 모양이다.

### 후보 5 — 분수 진수·음수 지수의 부호
**계산 손실수 칸 · 1방식만 · 태그에 다툼 있음 · 오늘 설문에 닿는다**

학생 보기: "식은 맞게 세웠는데 로그 값 부호에서 미끄러졌어요."

**왜 필요한가 — 식 하나로**

> log₂(1/8)

1/8 = 2⁻³ 이라 답은 **−3**. 학생은 8 = 2³ 만 보고 **3**이라 쓴다.
곱으로 이어지면 부호가 통째로 뒤집힌다 — log₃(1/9) × log₂8 = (−2)(3) = **−6** 인데 **6**이 된다.

**다툼이 있다.** 검증조 하나는 "1/8 = 2⁻³ 을 못 본 거니 계산이 아니라 **정의(공식 기억)** 쪽"이라고
반대로 판정했다. 계산 손실수 칸을 채우고 싶으면 후보 4와 이것 둘뿐인데,
태그가 틀리면 뒤에 붙는 296줄이 통째로 헛돈다.

**후보 4와 같은 칸이다. 둘 다 만들면 카드에 나란히 뜬다 — 하나만 고르는 자리다.**

### 후보 6 — 지수 증감 모델 세우기 (문장 → 지수식)
**식 세우기 칸 · 1방식만(검증은 통과) · 설문엔 버튼 없음**

학생 보기: "'매시간 20%씩 줄어든다' 같은 말을 지수식으로 옮기는 게 어려웠어요."

**왜 필요한가 — 식 하나로**

> 매시간 20%씩 줄어든다. 5시간 뒤 남은 양은?

정답: A₀ × 0.8⁵ = **0.32768 A₀** (20% 줄면 80%가 남으니 0.8을 다섯 번 곱한다.)
학생 오답 두 갈래:
- 선형으로: A₀(1 − 0.2 × 5) = **0** (0이 나오는데도 그냥 낸다)
- 밑을 감소율로: A₀ × 0.2⁵ = **0.00032 A₀**

세 값이 전부 다르다. **지수법칙을 한 줄도 쓰기 전에 이미 갈린다.**

**지금과 뭐가 다른가**

22개 후보 중 유일하게 활용·모델링을 건드린다. 저장소의 '식 세우기' 가족은 전부
"문제 말 → 식"이고(`g2_eq_setup` 등), 죽은 식 세우기 후보 셋은 전부 "식이 이미 주어진 상태"라 어긋났다.
**뜻이 실제로 맞는 유일한 식 세우기 후보다.**

### 후보 7 — 로그의 뜻
**개념 구멍 칸 · ⚠️ 적대적 검증 안 거침(1차 실행에만) · 후보 1과 같은 칸**

학생 보기: "log가 뭘 뜻하는지부터 헷갈렸어요."

**왜 필요한가 — 식 하나로**

> log₂8 = 3

이건 "**2를 몇 번 곱해야 8이 되나**"를 묻는 것이고 답이 3이다(2×2×2 = 8).
즉 log₂8 = 3 과 2³ = 8 은 **같은 말을 두 가지로 쓴 것**이다. 이걸 모르면 성질을 외워도 못 쓴다.

**⚠️ 두 가지:**
- 후보 1과 같은 개념 구멍 칸이다. 둘 다 만들면 카드에 "밑 1 미만 부등호 방향 오류 또는 로그의 뜻"으로 뜬다.
- 다시다에 오는 학생은 "틀린 문제를 들고 온" 고3이다. log의 뜻부터 모르는 학생이 그중 얼마나 되는지
  나는 모른다 — **그건 확인 안 했다.** 확인하려면 실제 사진 데이터를 봐야 한다.

**⭕ / ❌** →

### 잠글 만한 것 하나

## 3. 버려진 후보와 이유

짧게. 여기 교훈이 나머지 20개 풀이법에 그대로 쓰인다.

**지수↔로그 정의 변환** (3ˣ = 5 를 x = log₅3 으로 씀) — 실수는 실재한다.
버린 이유는 **붙일 칸이 없다.** '식 세우기'로 달면 식이 이미 주어져 있어 "문제 말 → 식"이 아니고,
정직하게 '공식 기억'으로 고치면 기존 둘과 3파전이 된다.
→ 교훈: **빈 칸이 있다는 건 근거가 아니다.**

**분수·음수 지수 계산 실수** (8^(−2/3)) — 세 방식이 각자 냈고 셋 다 죽었다.
근거 산수 자체가 틀렸다 — 8^(−3/2)는 1/16이 아니라 √2/32 ≈ 0.0442 다(1/16 = 0.0625).
→ 교훈: **근거로 쓴 오답은 반드시 끝까지 계산해서 낸다.** 식이 틀리면 그 판정은 버린다.

**치환식 세우기** (4ˣ = (2ˣ)² 를 못 봄) — 그걸 보는 게 곧 지수법칙·밑 통일이라
이미 있는 `g3_log_exp_base`와 같은 자리다.
→ 교훈: **뭉친 걸 쪼개면 자식이 부모의 개명이 되기 쉽다.**

**로그 성질 적용 오류** — `g3_log_exp`의 tip이 그 문장 그대로다("logₐb + logₐc = logₐ(bc)…").

**밑 통일 갈까 로그 씌울까** — 처방으로 내건 판정 규칙이 수학적으로 틀렸다.
그 규칙대로면 9ˣ = 27 을 "로그 씌워라"로 보내는데, 정답은 밑 3으로 맞춰 x = 3/2 다.
→ 교훈: **처방이 틀리면 이름표를 못 붙인다.**

**진수 안 덧셈** (log₂(8+8) = log₂8 + log₂8 = 6, 정답 4) — 이건 새 이름이 아니라
`review-content-map.ts` `g3_log_exp` step2의 **오답 보기 한 줄이 비어 있는 자리**다. 한 줄 추가로 끝난다.
파일 12개짜리가 아니다.

## 4. 부르는 법 4종 채점

나머지 20개 풀이법에 쓸 도구를 고르는 자리다. **B > D > A > C.**

| 방식 | 제출 | 생존 | 덮은 유형 | 재사용성 |
|---|---|---|---|---|
| B 유형칸 채우기 | 6 | 5 (같은 잣대로 재면 4) | 4 | 상 |
| D 처방 역산 | 5 | 3 | 3 | 상 |
| A 학생 눈 | 5 | 3 | 3 | 중 |
| C 쪼개기 | 6 | 3 | 3 | 하 |

**1위 B — "이 풀이법에서 개념 구멍은?"을 6번 묻는다.** 방식이 목적과 같은 모양이라 후보끼리 안 겹치고,
커버리지가 우연이 아니라 구조로 나온다. 20개 풀이법에 그대로 복붙된다.

**2위 D — "손으로 할 동작"이 안 나오면 후보가 못 태어난다.** 필터가 방식 안에 박혀 있다.
실제로 D만 계산 손실수 칸을 살려냈고, 스스로 빈 칸 하나를 안 채우고 비웠다.

**3위 A — 증거 품질은 제일 좋다.** 정답과 오답 구간이 겹치는지까지 계산했다.
내린 이유는 A가 자기 입으로 적었다: "지수·로그는 함정 자리가 교과서적으로 고정돼 있어서 쉬웠다."
방식의 힘이 아니라 단원의 성질이다. 미적분·확률에선 같은 값이 안 나온다.

**4위 C — 생성기로는 꼴찌.** 기각 3건의 사유가 전부 "이건 기존 것과 같다"였다.
쪼갤 뭉치가 없는 풀이법에선 출발조차 못 한다.
다만 C가 낸 부산물 하나는 값이 컸다 — 위 3번의 "오답 보기 한 줄" 발견이 C 쪽에서 나왔다.
