## 3. 수열 ② — 방향은 정해졌고 아직 안 만들었다

`g3_seq_sum_multiply_slip`(수열 × calc_slip). 막고 있던 학생 눈 판정이 09.19에 무효가 됐는데,
대조표를 만들어 보니 **다른 문제**가 나왔다.

### 같은 칸에 떨어지는 두 학생

문제: `aₙ=3n+2`일 때 `Σ(k=1~12)(2a_k−5)` · 정답 **456**

| | 학생 A | 학생 B |
|---|---|---|
| 실수 | `6·70=420` ✓, `6·8=48` ✓, **`420+8=428`** ✗ (십의 자리 흘림) | `6·78=468` ✓ (곱셈 맞음), **`−12`를 `+12`로** ✗ (부호) |
| 답 | 416 | 480 |
| 풀이법 · 실수유형 | sequence · calc_slip | **똑같다** |

②의 처방(`6·80=480` 어림 대조)을 대면:

```
A: |480 − 428| = 52 ≠ 12  → 걸림 ✓
B: |480 − 468| = 12 = 12  → 그냥 통과 ✗
```

**B는 곱셈을 안 틀렸는데 "곱셈 미끄러짐" 이름표를 받고, 처방도 안 듣는다.**

### 판정 (세 모델 일치)

> **빈 것 = 0, 틀린 것 = 마이너스.**

기윤이 이미 같은 판정을 잠가뒀다 — `weakness-mistake-type-map.ts:113`
"틀린 약점을 저장하면 그 뒤 복습이 통째로 헛도는데, **말풍선 한 번이 그것보다 싸다**" (08.11 🔒)

- ❌ **그대로 넣기** — 후보가 1개라 틀린 이름표가 박힌다. 셋 중 유일하게 미래 비용을 만든다
- ❌ **넓혀서 하나로** — A와 B를 **한 동작으로 잡는 검산이 없다**. Fable이 네 가지를 돌려봤다
- ✅ **약점 둘(곱셈/부호)** — 후보가 2개가 되면 카드에 `곱셈… 또는 부호…`로 뜬다.
  `photo-note-card.tsx:69`의 `' 또는 '`가 이미 그 일을 한다. **새 코드 0줄로 거짓을 안 준다**

덤 — **B를 잡는 처방은 새로 발명할 필요가 없다.** `g3_seq_sum_term`(①)의 tip과 같은 손동작이다
(n=1을 넣어 S₁과 나란히 대보기).

### 급한가

**E칸 열기 전까지는 젓가락급. E 문턱에서 예약급.**

지금은 이름표를 읽는 코드가 노트 카드 한 줄뿐이라 언제 넣어도 값이 같다.
E(노트→복습)가 `primaryWeaknessId`로 서버 과제를 만들기 시작하면 그때부터 틀린 이름표가
**서버 문서**가 되고 되돌리기가 비싸진다.

**단 "그대로 넣기"만은 지금 하면 E 때 반드시 비싸진다. 미루더라도 그건 빼고 미룬다.**

## 4. 새로 찾은 순서 — 말풍선이 E보다 먼저


**E를 열기 전에 말풍선이 있어야 한다.**
