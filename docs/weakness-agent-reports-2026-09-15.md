## 1. 미분 × setup_error(식 세우기) — **실재한다. 빈 칸이 맞다.**

**판정:** 미분 활용(최적화) 문항에서 제일 많이 죽는 자리가 여기다. 도함수는 멀쩡한데 세운 식이 틀려서 끝까지 틀린다.

**예제 A (고2 수학Ⅱ 미분 활용 표준형)**
> 한 변의 길이가 12인 정사각형 판지의 네 귀퉁이에서 한 변이 x인 정사각형을 잘라내고 접어 뚜껑 없는 상자를 만든다. 부피의 최댓값을 구하시오.

정답 풀이: 밑면 한 변은 **양쪽**에서 x씩 잘리므로 12-2x. V = x(12-2x)² = 4x³-48x²+144x, V' = 12x²-96x+144 = 12(x-2)(x-6), 0<x<6에서 x=2, **V=128**.

학생 풀이: 한쪽만 빼서 V = x(12-x)² = x³-24x²+144x. V' = 3x²-48x+144 = 3(x-4)(x-12), x=4, **V=256**. 미분도 인수분해도 방정식 풀이도 전부 정확한데 답은 2배.

**예제 B (제약조건 대입 · 대칭성 누락)**
> 곡선 y = -x²+9 (x축 위쪽)에 내접하고 y축에 대칭인 직사각형의 넓이의 최댓값.

정답: 가로 2t, 세로 9-t² → S = 18t-2t³, S' = 18-6t² = 0 → t=√3, **S = 12√3 ≈ 20.7846**.
학생: 가로를 t로 잡음 → S = 9t-t³, S' = 9-3t², t=√3은 똑같이 나오는데 **S = 6√3 ≈ 10.3923**. 임계점이 같아서 학생은 검산으로도 못 잡는다.

**근거 한 문단.** 두 예제 모두 f'(x) 계산, f'(x)=0 풀이, 증감 판정이 전부 옳다. 틀린 건 문장을 식으로 옮기는 첫 줄 하나뿐이고, 그 뒤 모든 단계가 그 틀린 식 위에서 정확하게 굴러간다. 지금 diff에 달린 넷 중 어느 것으로도 이 학생을 못 잡는다 — derivative_calculation은 규칙을 의심하게 만들고(규칙은 맞았다), solving_order·g2_diff_application은 f'(x)=0 **이후**를 말하며(이후는 맞았다), max_min은 볼록 방향을 말한다(그것도 아니다). 칸이 비어 있는 게 아니라, 이 학생이 잘못된 처방을 받거나 후보 0개로 떨어진다.

**제안 이름:** 「변수 하나로 식 세우기 오류」
**tip:** 미분하기 전에 그림 옆에 `가로=__ · 세로=__ · 높이=__`를 전부 x로 적고, 잘린 쪽이 한쪽인지 양쪽인지 그림에 화살표 두 개를 그어라.

## 2. 미분 × calc_slip(계산 손실수) — **실재한다. 그리고 formula_recall과 가르는 선이 수학적으로 있다.**

**판정:** 있다. 다만 선을 "도함수 규칙을 건드렸나"가 아니라 **"미분 이후 산술인가"**로 그어야 깨끗하다.

**예제 (극값 대입 산술)**
> f(x) = x³-3x²-9x+1 의 극댓값을 구하시오.

f'(x) = 3x²-6x-9 = 3(x+1)(x-3) → x = -1, 3. 극대는 x=-1.
f(-1) = (-1)³ - 3(-1)² - 9(-1) + 1 = -1 - 3 + 9 + 1 = **6**.
학생: -3(-1)²의 제곱을 먼저 안 하고 -3·(-1) = +3으로 처리 → -1 + 3 + 9 + 1 = **12**. (검산: 코드로 f(-1)=6, 미끄러진 경로 12 확인)

여기서 도함수 3x²-6x-9는 한 글자도 안 틀렸다. 지수도 계수도 규칙대로 내려왔다. 틀린 건 대입 한 줄의 부호다.

**derivative_calculation(공식 기억)과 뭐가 다른가 — 기계적 판별법이 있다.**
학생이 쓴 f'와 정답 f'를 **차수 패턴**으로 비교하면 된다.
- xⁿ이 xⁿ⁻¹로 안 내려갔거나(예: x⁴을 미분해 4x⁴), 상수항이 안 죽었거나, (fg)' = f'g'를 썼다 → 규칙이 틀린 것 = **formula_recall**
- 차수 패턴은 전부 맞고 계수·부호 하나만 어긋났거나, **f'이 나온 뒤**의 방정식 풀이·대입에서 틀렸다 → **calc_slip**

경계가 흐린 자리는 딱 하나다: 3x²을 미분해 6x가 아니라 3x라고 쓰는 경우(지수는 내렸는데 곱을 빼먹음). 이건 어느 쪽으로도 읽힌다. 그래서 calc_slip 칸의 정의를 **"f'(x)를 구한 다음의 계산"**으로 좁히면 겹침이 0이 된다 — 위 예제가 그 자리다. 억지가 아니라, 지금 derivative_calculation의 desc(`data/diagnosisMap.ts:178`, "x^n 미분 규칙 적용이 흔들려")가 이미 규칙 쪽만 말하고 있어서 남는 자리가 그대로 비어 있는 것이다.

**제안 이름:** 「극값 대입 계산 실수」
**tip:** f(x)에 대입할 때 x 자리를 반드시 괄호로 감싸 `(-1)³ / -3(-1)² / -9(-1)` 처럼 항마다 줄을 바꿔 적고, 거듭제곱을 먼저 계산해 그 줄 끝에 값을 적어라.

## 3. 미분 × answer_read(마무리 해석) — **실재한다. 단, 절반은 5번과 충돌한다.**

**판정:** 극값↔극값이 되는 x 혼동은 순수한 answer_read다. 끝점 누락은 answer_read가 아니라 procedure_miss 쪽에 가깝다 — 이건 갈라서 봐야 한다.

**예제 A (순수 answer_read)**
> f(x) = x³-6x²+9x+2 의 극솟값을 구하시오.

f'(x) = 3x²-12x+9 = 3(x-1)(x-3) → x=1, 3. x=3에서 극소.
극솟값 = f(3) = 27-54+27+2 = **2**. (극댓값은 f(1)=6)
학생 답: **3**. 즉 "극솟값"을 물었는데 "극소가 되는 x"를 썼다. 계산은 전부 맞다. 게다가 오답 3과 정답 2가 둘 다 작은 정수라 학생 눈에 이상해 보이지 않는다.

**예제 B (경계선 — 끝점)**
> 닫힌구간 [-1, 4]에서 f(x) = x³-3x²+2 의 최댓값.

f'(x) = 3x²-6x = 3x(x-2) → x=0, 2. f(-1) = -2, f(0) = 2, f(2) = -2, f(4) = **18**.
최댓값은 끝점 x=4의 18인데, 극댓값만 본 학생은 2를 쓴다.

**근거 한 문단.** 예제 A는 `features/photo/flow/mistake-types.ts:29-32`의 정의("다 풀고 문제가 뭘 물었는지에서 틀림")에 정확히 맞는다 — 수학적 작업이 100% 끝난 뒤 문장 해석에서만 넘어진다. 예제 B는 다르다. 끝점 비교는 닫힌구간 최대·최소 **절차의 한 단계**라서, 같은 파일 25-28줄의 procedure_miss("단계를 빼먹음") 정의에도 똑같이 맞는다. 그래서 B를 answer_read에 넣으면 5번의 두 후보와 세 번째로 겹친다. answer_read 칸은 A만 담는 게 안전하다.

**제안 이름:** 「극값과 그 x 혼동」 (이차함수판 min_value_read_confusion의 미분판, `data/diagnosisMap.ts:153-159`와 같은 꼴)
**tip:** 답을 쓰기 전 노트 맨 아래에 `x = __ / f(x) = __` 두 칸을 그려 값을 각각 채우고, 문제 문장에서 물은 쪽 칸에 동그라미를 쳐라.

## 4. 미분 × concept_gap → max_min_judgement_confusion — **정당하지 않다. tip이 삼차함수에서 깨진다.**

**판정:** 어긋남. `data/diagnosisMap.ts:188-194`의 topicLabel은 '이차함수', tip은 `'a>0은 최솟값, a<0은 최댓값을 먼저 판단한 뒤 값을 계산하세요.'` — 삼차 이상에서 이 문장은 거짓이다.

**반례 (수능 표준형)**
> 닫힌구간 [-3, 2]에서 f(x) = x³-3x 의 최댓값과 최솟값을 구하시오.

f'(x) = 3x²-3 = 3(x+1)(x-1) → x = -1, 1.
f(-3) = -27+9 = **-18**, f(-1) = -1+3 = **2**, f(1) = 1-3 = **-2**, f(2) = 8-6 = **2**.
→ 최댓값 2, 최솟값 **-18**. (전부 코드 검산)

이 한 문제가 tip을 두 번 깬다.
- a = 1 > 0인데 **최댓값이 존재한다** (2). "a>0이면 최솟값"이라는 판단 자체가 성립 안 한다.
- 최솟값은 극솟값 -2가 아니라 끝점의 **-18**이다. 볼록 방향으로 먼저 판단한 학생은 -2를 쓴다.

**추가 반례 — 도함수가 0인데 극값이 아닌 경우**
f(x) = x³ 에서 f'(x) = 3x², f'(0) = 0. 그런데 f(-1) = -1 < f(0) = 0 < f(1) = 1로 계속 증가한다. x=0은 극값이 아니다. 이차함수에는 존재할 수 없는 상황이라, 이차함수 처방으로는 이 학생을 절대 못 건드린다.

**근거 한 문단.** 이차함수에서는 꼭짓점이 유일한 극값이자 전체 최대/최소여서 "a의 부호 → 최대인지 최소인지"가 항상 옳다. 삼차 이상에서는 (ㄱ) f'(x)=0이 극값을 보장하지 않고, (ㄴ) 극값이 최대·최소를 보장하지 않으며, (ㄷ) 최고차항 부호가 최대·최소의 존재를 보장하지 않는다. 셋 다 위에서 숫자로 확인했다. 미분으로 풀다 개념에서 막힌 학생에게 이 tip이 나가면 처방이 안 맞는 정도가 아니라, 학생이 이미 갖고 있는 잘못된 규칙("a>0이면 최솟값")을 앱이 공인해준다. `features/photo/flow/weakness-mistake-type-map.ts:26-29` 주석이 이미 이 문제를 알고 적어놨고("미분에서 막힌 학생에게 이차함수 처방"), 제 검산 결과는 그 주석이 맞다는 쪽이다.

**제안 이름:** 「극값 판정 개념 구멍」
**desc(제안):** f'(x)=0인 x가 항상 극값은 아니고, 극댓값이 항상 최댓값도 아닙니다 — 부호 변화와 끝점 비교로 결정합니다.
**tip:** f'(x)=0인 x마다 그 좌우 숫자를 하나씩 f'에 대입해 `+`나 `−`를 적고, 부호가 안 바뀐 x에는 ×표를 쳐라.

## 5. solving_order_confusion vs g2_diff_application — **수학적으로는 다른 실수. 그런데 처방이 같아서 가른 값이 없다.**

**판정:** 서로 다른 동작이다. 동작을 가르는 예제를 만들 수 있다. 다만 두 tip이 사실상 같은 문장이라, 학생이 어느 쪽을 받든 받는 지시가 같다.

**공통 문제**
> f(x) = x³-3x²-9x+11 의 극댓값을 구하시오.

f'(x) = 3x²-6x-9 = 3(x+1)(x-3) → x = -1, 3.
f'(-2) = 15 > 0, f'(0) = -9 < 0, f'(4) = 15 > 0 → x=-1에서 극대, x=3에서 극소.
f(-1) = -1-3+9+11 = **16**, f(3) = 27-27-27+11 = **-16**. 정답 16. (코드 검산)

**학생 A (solving_order_confusion만 틀림):** f'(x)=0을 풀어 x=-1, 3까지 정확히 얻고 "극대는 x=-1" 까지 맞춘 뒤, **f(-1)을 안 구하고 답을 -1로 쓴다.** 증감 판정은 성공했다.

**학생 B (g2_diff_application만 틀림):** f(-1)=16, f(3)=-16을 **둘 다 정확히 계산해놓고**, 증감표를 안 그린 채 "x가 큰 쪽이 극대"라고 짚어 답을 **-16**으로 쓴다. 대입 단계는 성공했다.

A는 4단계 중 3단계를 빼먹었고, B는 3단계는 했는데 4단계 판정을 뒤집었다. 한 학생이 하나만 틀리고 다른 하나는 안 틀리는 문제를 이렇게 만들 수 있으니, **같은 실수를 두 번 적은 건 아니다.**

**그런데 문제가 둘 더 있다.**

첫째, tip이 겹친다. `data/diagnosisMap.ts:186`은 `'x 도출 -> 원함수 대입 -> 최댓값/최솟값 판정의 3단계를 체크리스트로 유지하세요.'`, `:404`는 `"f'(x)=0의 x값 → 증감표 작성 → 극값 결정의 3단계를 순서대로 적어보세요."` 둘 다 "3단계를 적어라"다. `features/photo/flow/weakness-mistake-type-map.ts:109-116`에 따르면 후보가 둘 남으면 학생에게 말풍선으로 묻게 되어 있는데, 물어서 갈라봐야 나가는 지시가 같으면 그 질문은 학생 시간만 쓴다.

둘째, A의 실수는 3번 칸(answer_read)과 정면으로 겹친다. "x를 구해놓고 f(x)를 안 구해서 x를 답으로 쓴다"는 3번 예제 A와 학생 동작이 똑같다. 즉 같은 학생이 사진을 찍었을 때 AI가 procedure_miss로 읽으면 solving_order, answer_read로 읽으면 3번 새 약점으로 가고, 둘이 다른 처방을 준다.

**어느 쪽 문구가 더 정확한가 —** g2_diff_application 쪽이다. 증감표는 극대·극소를 실제로 **결정하는 도구**를 이름으로 부르고 있고, 학생 B의 실수(부호 변화를 안 보고 값 크기로 판정)를 정확히 겨눈다. solving_order의 desc("대입하는 순서가 누락")가 가리키는 동작은 `features/photo/flow/mistake-types.ts:29-32`의 answer_read 정의와도 맞아서 칸이 흔들린다. 제 권고는 **procedure_miss 칸은 g2_diff_application 하나로 두고, solving_order가 잡던 "x를 답으로 씀"은 3번의 answer_read 칸으로 옮기는 것**이다. 다만 이건 권고고, 실측 판정은 기윤 몫이다.

## 6. 미분 × formula_recall → derivative_calculation — **tip이 곱·합성을 못 덮는다.**

**판정:** 안 덮는다. `data/diagnosisMap.ts:179`의 tip `'지수는 앞으로 곱하고 지수는 1 감소한다는 패턴을 항별로 분리해 적용하세요.'`는 xⁿ 하나짜리 항에만 참이고, "항별로 분리"라는 말이 곱해진 괄호에 그대로 적용되면 오히려 틀린 답을 만든다.

**반례 A (곱의 미분)**
> f(x) = (x²+1)(x³-2x) 일 때 f'(1)의 값을 구하시오.

전개: f(x) = x⁵-x³-2x → f'(x) = 5x⁴-3x²-2 → **f'(1) = 0**.
곱의 미분법으로도 동일: (2x)(x³-2x) + (x²+1)(3x²-2) = 5x⁴-3x²-2 ✓ (코드로 두 경로 일치 확인)
tip대로 "항별로 분리"한 학생: (x²+1)' · (x³-2x)' = 2x(3x²-2) = 6x³-4x → **f'(1) = 2**. 부호나 계수 하나가 아니라 식 자체가 다른 함수가 된다.

**반례 B (합성함수)**
> f(x) = (2x-1)⁴ 일 때 f'(1).

전개: 16x⁴-32x³+24x²-8x+1 → f' = 64x³-96x²+48x-8 → **f'(1) = 8**. (= 8(2x-1)³ 에 x=1 대입)
tip만 가진 학생: "지수 4를 앞으로, 지수 1 감소" → 4(2x-1)³ → f'(1) = **4**. 안쪽 미분 2배가 통째로 빠진다.

**근거 한 문단.** 제 기억으로는 고2 수학Ⅱ 범위에 이미 "함수의 실수배·합·차·곱의 미분법"이 들어 있어서, `diff` 갈래를 타는 학생이 반례 A를 실제로 만난다 — 다만 교육과정 문서를 확인한 건 아니고 기억입니다. 반례 B(합성)는 고3 미적분 범위다. 그리고 넓은 문구를 가진 약점이 저장소에 이미 있긴 하다 — `g3_diff`의 desc가 `'다항함수·합성함수·곱의 미분 계산에서 오류가 발생했습니다.'`(`data/diagnosisMap.ts:449-455`)인데, 이건 `data/diagnosisTree.ts:721-745`의 **`diff_advanced`** 갈래에만 달려 있다. 즉 `diff`로 분류된 학생은 어떤 경로로도 그 문구를 못 받는다. 지금 구조에서 derivative_calculation은 다항식 한 항짜리 학생만 커버하고, 괄호 곱이 섞인 순간 처방이 오답을 가리킨다.

**tip 대안:** 괄호끼리 곱해진 식이면 미분하기 전에 먼저 전개해서 xⁿ 항들로 펴 쓰고, 전개가 안 되는 꼴이면 `(앞)'×(뒤)`와 `(앞)×(뒤)'` 두 덩어리를 각각 다른 줄에 적은 뒤 더해라.
(이 대안도 고2 다항식까지만 참이다. 지수·로그·삼각이 섞이는 고3 미적분은 `diff_advanced`/`g3_diff` 쪽 몫이다.)

## 2. 적분 × 식 세우기 · 극한 공유 약점 (math-teacher)

> 실측 1건(정적분 넓이를 signed integral로 세운 학생)의 출발점이 된 판정이다.
> `g2_diff_application`이 미분·적분 둘 다에 달려 있어 한쪽만 좁히면 다른 쪽이 망가진다는 것,
> `g3_limit` 하나가 함수극한·수열극한 둘에 달려 있다는 것도 여기서 나왔다.

## (1) 넓이를 signed integral로 세운 실수 — `integral` + `setup_error`

**[판정] 수학적으로 말 되는 실수고 수능에 실제로 나온다. 그런데 `integral`에 달린 세 약점 중 이걸 담을 수 있는 건 하나도 없다. 그리고 지금 코드는 틀린 이름표를 붙이는 게 아니라 이름표를 하나도 안 붙인다 — 빈 배열이 나온다.**

[예제+풀이]

> 곡선 y = x³ − 4x 와 x축으로 둘러싸인 도형의 넓이를 구하시오.

맞는 풀이: x³ − 4x = x(x−2)(x+2) → 교점 x = −2, 0, 2. 부호가 바뀌는 자리에서 구간을 끊는다.
∫₋₂⁰ (x³−4x)dx = **4**, ∫₀² (x³−4x)dx = **−4**. 넓이 = |4| + |−4| = **8**.

학생 풀이: 넓이니까 ∫₋₂² (x³−4x)dx 한 번에. = 4 + (−4) = **0**. 답 0.

여기서 학생이 틀린 자리는 계산이 아니다. 원시함수 x⁴/4 − 2x² 도 맞고, 끝값 대입도 맞다. **틀린 건 "넓이 = 정적분값"이라고 식을 세운 것** — 넓이는 ∫|f(x)|dx 인데 ∫f(x)dx 로 세웠다. 그래서 `setup_error`(식 세우기)는 정확한 태그다. (전부 유리수 정밀 계산으로 확인했다. 같은 구조가 y = x² − 2x, [0,3] 에서도 나온다 — 참값 8/3, 통째 적분값 0.)

수능에 나오는가: 이 실수를 앱 자신이 이미 알고 있다. `data/diagnosisTree.ts:713` 의 선택지 문장이 `'정적분으로 넓이 계산할 때 절댓값 처리가 어려웠어요.'` 다. 다만 그 선택지는 `integral_advanced`(심화 적분) 아래에만 있고, 거기 붙은 `g3_integral` 의 태그는 `concept_gap` 이다 (`weakness-mistake-type-map.ts:74`). 즉 `setup_error` 로는 심화 쪽에서도 못 잡는다.

[근거]
`data/diagnosisTree.ts:407~427` 의 `integral` 선택지는 셋뿐이고, 각각 `g2_integral_basic`·`g2_integral_definite`·`g2_diff_application` 이다. 태그는 순서대로 `formula_recall`·`calc_slip`·`procedure_miss` (`features/photo/flow/weakness-mistake-type-map.ts:63~65`). `setup_error` 는 그 셋 안에 없다. `weaknessCandidatesFor` 는 `:128` 에서 태그가 다른 후보를 전부 걷어내므로 `('integral','setup_error')` → `[]`. 실제로 데이터를 그대로 읽어 함수 로직을 재현해 돌려봤고, `integral` 의 6칸 중 `concept_gap`·`setup_error`·`answer_read` 셋이 빈 배열이었다. 셋 중 어느 것도 이 실수를 못 담는 이유는 각각 다르다 — `g2_integral_basic` 은 `∫xⁿdx` 공식의 지수·계수 처리(=원시함수 구하는 단계)인데 학생은 원시함수를 맞게 구했고, `g2_integral_definite` 는 F(b)−F(a) 대입 순서·부호인데 학생은 대입도 맞게 했다(∫₋₂² 는 정말로 0이다. 계산이 다 맞았는데 답이 틀린 경우라 `calc_slip` 자체가 성립을 안 한다), `g2_diff_application` 은 적분이 아니라 미분 얘기다. 없다.

## (2) `integral` + `procedure_miss` → `g2_diff_application`(미분 활용 오류)

**[판정] 절반만 정당하다. 이 이름표가 맞는 적분 문제가 실제로 있지만, `procedure_miss` 로 들어오는 적분 실수의 대부분은 미분과 아무 상관이 없고 그것들까지 전부 "미분 활용 오류"를 받는다.**

[예제+풀이] — ① 이름표가 맞는 경우

> 함수 F(x) = ∫₀ˣ (t² − 2t)dt 에 대하여 구간 [0,3] 에서 F(x)의 최솟값을 구하시오.

F(x) = x³/3 − x². 미적분의 기본정리로 F′(x) = x² − 2x = x(x−2) → x = 2.
증감표: [0,2] 감소, [2,3] 증가. F(0) = 0, F(2) = **−4/3**, F(3) = 0. 최솟값 **−4/3**.

여기서 학생이 "F′(x)=0 까지는 구했는데 증감표를 안 그리고 끝점만 비교해서 0이라고 썼다"면 이건 진짜로 미분 활용(증감표→극값) 단계의 절차 누락이다. `g2_diff_application` 의 desc가 `"f'(x)=0의 해를 구한 뒤 증감표로 최댓값·최솟값을 결정하는 단계"` (`data/diagnosisMap.ts:403`) 라서 문구까지 정확히 맞는다.

[예제+풀이] — ② 이름표가 안 맞는 경우 (같은 칸으로 들어온다)

> ∫₀³ |x² − 2x| dx 의 값을 구하시오.

x² − 2x = x(x−2) 라 [0,2]에서 음수, [2,3]에서 양수 → 절댓값을 벗기며 구간을 둘로 끊는 절차가 필요하다.
−∫₀² (x²−2x)dx = **4/3**, ∫₂³ (x²−2x)dx = **4/3**. 합 **8/3**.
절댓값을 그냥 지우고 ∫₀³ (x²−2x)dx 로 가면 **0**.

여기서 빠진 건 "부호 구간으로 쪼개는 절차"다. 미분은 한 번도 안 나온다. 그런데 AI가 `('integral','procedure_miss')` 를 보내면 이 학생이 받는 이름표도 **미분 활용 오류**고, 처방도 `"f'(x)=0의 x값 → 증감표 작성 → 극값 결정의 3단계를 순서대로 적어보세요"` 다. 절댓값을 벗기다 넘어진 학생한테 증감표를 그리라고 시킨다.

[근거]
진단 flow에서는 이 자리가 성립한다 — 학생이 `data/diagnosisTree.ts:422~425` 의 선택지 `'적분보다 미분 활용(최댓·최솟값) 단계에서 막혔어요.'` 를 **자기 손으로** 골랐으니, 미분 이름표가 붙는 게 맞다. 문제는 사진 flow가 그 선택지 문장을 안 쓰고 `(methodId, mistakeType)` 두 값만으로 같은 칸을 집는다는 점이다. `integral` 아래 `procedure_miss` 태그를 가진 약점이 `g2_diff_application` 하나뿐이라(`weakness-mistake-type-map.ts:63`) 적분에서 나오는 모든 절차 누락 — 절댓값 구간 분할 누락, 넓이 문제에서 교점을 안 구함, 치환적분에서 적분구간을 u로 안 바꿈(∫₀¹ 2x(x²+1)³dx: u = x²+1, u는 1→2 라 정답 **15/4**, 구간을 0→1로 두면 **1/4**) — 이 전부가 한 이름표로 떨어진다. "정당한가"에 대한 답은: 위 ① 한 종류에만 정당하고, 그 외에는 부당하다. 앞 문단 ①②의 두 문제는 `methodId`·`mistakeType` 이 똑같이 들어올 수 있는데 필요한 처방은 완전히 다르다.

## (3) `g3_limit` 하나가 `limit` 과 `sequence_limit` 에 같이 달린 것

**[판정] 겹치는 지점이 한 군데 있지만(∞/∞ 최고차항 나누기), 나머지는 서로 다른 실수다. 특히 지금 `g3_limit` 의 설명·처방 문구가 함수의 극한만 가리키고 있어서 수열 쪽 학생한테는 처방이 안 맞는다.**

[예제+풀이] — 함수의 극한

> lim(x→0) (√(x+4) − 2)/x 의 값을 구하시오.

그냥 대입하면 0/0. 분자를 유리화한다 — 분자·분모에 (√(x+4)+2)를 곱하면
(x+4−4) / [x(√(x+4)+2)] = 1/(√(x+4)+2) → x=0 대입 **1/4**.
(수치로 확인: x=±10⁻⁵ 에서 0.2499998 / 0.2500002.)

학생이 틀리는 자리: 0/0을 보고 "값이 없다/0이다"로 처리하거나, 유리화·인수분해로 0을 소거하는 절차를 모른다. 여기에는 **좌·우극한**이라는 것도 있다 — lim(x→0) |x|/x 는 오른쪽에서 +1, 왼쪽에서 −1이라 극한이 존재하지 않는다 (수치 확인: x=+10⁻⁶ → 1.0, x=−10⁻⁶ → −1.0).

[예제+풀이] — 수열의 극한

> lim(n→∞) (3n² + 2n)/(n² − 5) 의 값을 구하시오.

분자·분모를 n²으로 나눈다 → (3 + 2/n)/(1 − 5/n²) → **3**.
(수치 확인: n=10⁴ → 3.00020, n=10⁶ → 3.0000020.)

> 수열 aₙ = (rⁿ − 1)/(rⁿ + 1) 이 수렴하도록 하는 r의 값에 따라 극한을 구하시오. (r > 0)

여기가 함수 극한과 갈라지는 자리다. |r| < 1 이면 rⁿ → 0 이라 극한 **−1**. r = 1 이면 모든 항이 0이라 **0**. r > 1 이면 분자·분모를 rⁿ으로 나눠 (1 − r⁻ⁿ)/(1 + r⁻ⁿ) → **1**. (r = 1/2, 1, 2 각각 수치 확인: −1.0, 0.0, 1.0.)

학생이 틀리는 자리는 인수분해가 아니라 **r의 범위로 경우를 나누는 판정**이다. 그리고 수열에는 좌극한이 없다 — n은 자연수라 한쪽에서만 간다. 0/0 꼴도 수열 극한에선 거의 안 나온다.

[근거]
겹치는 칸은 딱 하나다. `data/diagnosisTree.ts:527~530` 의 `'∞/∞ 꼴에서 최고차항으로 나누는 처리가 어려웠어요.'` 와 `:689~692` 의 `'∞/∞ 꼴에서 극한값을 구하는 처리가 막혔어요.'` 는 사실상 같은 동작을 가리킨다 — 이 한 칸은 약점을 공유해도 된다. 문제는 나머지 넷이다. `limit` 쪽 `lim_zero`(0/0 처리)·`lim_factor`(공통인수 약분)는 함수 고유, `sequence_limit` 쪽 `sl_converge`(수렴·발산 판정)·`sl_geom`(|r|<1 조건)은 수열 고유인데, 여섯 선택지 전부가 `g3_limit` 하나로 떨어진다. 그리고 `data/diagnosisMap.ts:491~497` 의 `g3_limit` 은 desc가 `"함수의 극한 계산 과정에서 0/0 꼴 처리나 인수분해가 미숙합니다"`, tip이 `"0/0 꼴은 분자·분모를 인수분해해 공통인수를 약분한 뒤 대입하세요"` 다. 등비수열 수렴 조건에서 넘어진 학생이 받는 처방이 이것이다 — 위 rⁿ 문제에서 인수분해할 게 없다. 이름표를 공유한 게 문제라기보다, **공유한 이름표의 문구가 두 영역 중 한쪽만 설명하고 있다**는 게 문제다.

덧붙여, 이 셋을 확인하다 같이 나온 것: 데이터를 그대로 읽어 `weaknessCandidatesFor` 로직을 재현해 돌려보니 `limit`·`sequence_limit`·`integral_advanced` 는 셋 다 6칸 중 `concept_gap` 한 칸만 차 있고 나머지 5칸이 빈 배열이었다. 선택지 3개가 전부 같은 약점 하나를 가리키니 태그도 하나뿐이라 그렇다.

# ■ 원문 없는 반응 — 판정 없음

### A. 프라임 `′`가 먼지처럼 보였어요

읽힌 것 — `(앞)′×(뒤)`에서 `′`를 처음에 따옴표나 화면 때인 줄 알았어요. 바로 윗줄 설명에는 `f'(x)`로 아포스트로피가 쓰여 있는데 처방에선 다른 기호가 나와서, **같은 노트 안에 프라임이 두 종류**예요. "이게 미분이라는 뜻인가 아니면 오타인가" 하고 한 번 멈췄어요. `x^n`도 손으로는 위첨자로 쓰는 거라 `^`가 한 박자 걸렸고요. 반대로 `f'(x)`랑 `×표`는 안 걸렸어요 — 그건 원래 쓰는 거예요.

어느 층 — **② 층.** 기호가 뭔지 되짚는 데 시간 쓰느니 문제 하나 더 푸는 쪽이라, 여기서 바로 나가요.

※ 원문 없음 — 화면에서 `′`가 어떻게 보이는지는 확인된 사실이 아니라 제 반응이에요.

### B. ①의 설명 줄은 두 번 읽어야 했어요

읽힌 것 — "f'(x)=0인 x가 **항상 극값은 아니고**, 극댓값이 **항상 최댓값도 아닌데**" — 한 문장에 "항상 ~아니다"가 두 번이라 뭐가 뭐 아니라는 건지 되감아야 했어요. 두 번째 읽을 때 이해했는데, 첫 줄에서 두 번 읽게 만들면 두 번째 줄로 안 가요.

어느 층 — **② 층.** 문장 되감기는 "오답에 오랜 시간 쓰기 싫다"는 쪽이 제일 먼저 포기하는 동작이에요.

※ 원문 없음 — 이중부정이 안 읽힌다는 건 제 반응이지 오르비에서 확인한 게 아니에요.
