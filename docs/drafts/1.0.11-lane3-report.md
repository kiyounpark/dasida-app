# 1.0.11 3줄 보고 — 다른 기기 보기 (읽기 쪽) · 2026-10-02 15:26 KST

## 결론 먼저

- 서버 두 함수(`listPhotoNotes`·`getPhotoNoteImage`)는 본문을 채워 **운영에 배포했다**(10.02 15:19~15:20 KST). 인증 없는 GET이 401 `UNAUTHORIZED`로 돌아오는 것까지 확인했다.
- 앱 쪽(서버 목록 읽기·사진 내려받기·지난 노트 화면 합치기)은 다 짰고 테스트로 덮었다.
- **그런데 지금 main에 합쳐도 학생 화면에선 서버를 안 부른다.** 주소 파일 `app/photo-notes.tsx`가 화면에 `getRemoteAuthHeaders`를 내려줘야 하는데, 그 파일이 담당 표 밖이라 손대지 않았다. 통합 때 한 줄이면 된다(아래 「담당 밖」).

## 한 일

**서버**
- `listPhotoNotes` — `users/{accountKey}/photoNotes`를 `createdAt` 내림차순으로. `before`(createdAt 커서, 그보다 오래된 것만)·`limit`(기본 100, 최대 200). limit+1개를 읽어 더 있으면 `nextBefore` = 그 쪽 마지막 `createdAt`, 없으면 null. `deletedAt` 있는 문서도 준다. createdAt 한 칸 정렬·범위라 복합 색인이 필요 없다.
- `getPhotoNoteImage` — 문서의 `photoPath`를 서버가 읽어 JPEG 바이트(`Content-Type: image/jpeg`, `Cache-Control: private, no-store`). 사진 없음(문서 없음·`photoPath` null·Storage 객체 없음) = 404 `PHOTO_MISSING`. 쿼리는 `accountKey`·`noteId`만 받고 다른 칸은 zod가 버린다.
- 약속 파일 밖으로 하나씩 더 막은 것: 지운 노트는 410 `NOTE_DELETED`(약속 파일 오류 표에 있는 코드, 1.0.11엔 늘 null이라 안 탄다) · `photoPath`가 이 계정 폴더(`accountNotePhotoPrefix`) 밖이면 안 준다 · `noteId`에 `/`가 섞이면 400(Firestore가 경로로 읽지 않게).

**앱** — 새 `features/photo/cloud/remote-note-store.ts`
- 서버 목록을 커서 따라 끝까지 읽는다(쪽당 200, 최대 10쪽, 커서가 안 나아가면 멈춤). 모양이 깨진 문서는 버린다.
- 사진은 같은 인증 헤더로 캐시에 받은 뒤 `persistNotePhoto`로 문서 폴더에 옮긴다 — 파일명 규칙(`safeNoteFileStem`)·폴더를 `photo-file-store` 한 집에 두려고. 앱은 경로를 안 보낸다.
- 합치기: 같은 id면 기기 것 우선. `deletedAt` 있는 건 안 그린다. 서버 실패·오프라인·401 = 아무것도 안 넘김(화면은 기기 노트만, 오류 띠 없음). 서버 노트는 `toLocalNote`로 폰 모양(서버 칸 빠지고 `cloudStoredAt`·`submissionId` 붙음).
- 화면엔 두 번 넘긴다 — 목록이 오면 글 먼저, 사진까지 받으면 한 번 더. 사진은 넷씩 받는다.

**지난 노트 화면** `photo-notes-screen.tsx`
- 기기 노트를 먼저 그리고 서버 노트를 뒤에 더한다. `getRemoteAuthHeaders` prop이 없으면 서버를 안 부른다(지금 주소 파일 상태).
- 기기 노트가 0장이고 서버 답을 기다리는 중이면 「아직 노트가 없어」 대신 빈 화면 + 도는 표시. 새 기기에서 노트가 있는데 "없어"가 몇 초 뜨면 거짓말이라서다. 새 글자는 화면 읽기용 이름표 「노트 불러오는 중」 하나뿐이다(보이는 문구 0).

## 제가 혼자 정한 것 하나 — 확인 부탁

**가져온 노트를 이 기기에 남긴다**(note-store의 있는 함수 `savePhotoNote`로). lanes 문서엔 "합친다"만 있고 남길지는 안 적혀 있다.
남긴 이유: 사진을 문서 폴더에 받는데 노트가 기기 목록에 없으면, 로그아웃·탈퇴 때 `clearPhotoNotes`가 그 사진을 못 찾는다 — 학생은 지웠다고 아는데 기기에 사진이 남는다. 덤으로 다음엔 오프라인이어도 보인다.
대신 사진을 못 받은 노트는 남기지 않는다(남기면 "기기 것 우선"에 걸려 다시 안 받는다 — 그 장은 다음에 열 때 다시 받는다). 화면을 떠나면 남기기를 멈추고 받아 둔 사진은 지운다.
복습 과제는 안 건드린다 — 이 길이 부르는 서버는 `listPhotoNotes`·`getPhotoNoteImage`뿐이고, 기기에 쓰는 건 `savePhotoNote`뿐이다(테스트로 확인).

## 못 한 것

- 실제 노트가 있는 계정으로 목록·사진이 오는지는 **안 봤다** — 시뮬레이터·실기기·운영 테스트 문서를 쓰지 말라는 지시대로 함수 테스트·앱 테스트로만 확인했다. 2줄 저장이 들어간 뒤 두 기기 확인 때 처음 보게 된다.
- 「서버에 없는 노트 올리기」(4번) — 지시대로 안 만듦.
- 독립 리뷰(다른 모델·에이전트) 안 돌림.

## 모르는 것

- **`File.downloadFileAsync`가 실기기에서 헤더를 싣고 도는지** — 타입 정의(`expo-file-system` 19.0.22 `DownloadOptions.headers`)만 봤다. 비 2xx면 파일 없이 거절한다고 적혀 있다(같은 정의 파일). 404와 500을 못 가른다 — 그래서 사진 실패는 전부 "이번엔 글만, 다음에 다시"로 묶었다.
- `listPhotoNotes`의 커서는 `createdAt` 하나다(약속 파일 그대로). 같은 createdAt을 가진 노트 둘이 쪽 경계에 걸리면 하나가 빠진다 — 노트 id가 `photo-{createdAt}`(밀리초)라 겹칠 일은 없다고 봤다.
- 서버에선 지워졌는데(`deletedAt`) 이 기기엔 같은 id가 있는 노트는 **보인다**(기기 것 우선). 1.0.11엔 지우는 길이 없어 안 생기는 경우다. 지우기가 붙을 때 다시 봐야 한다.
- 로그아웃이 `savePhotoNote` 한 번이 도는 그 순간(읽고-쓰기 사이)에 겹치면 그 한 장이 다시 쓰일 수 있다. 화면을 떠나는 순간부터는 안 쓰니 창은 한 번의 쓰기 길이다.
